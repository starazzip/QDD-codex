# QDD Codex

[English](README.md) | [繁體中文](docs/i18n/README.zh-TW.md)

QDD Codex is a Codex-first, question-driven development workflow. It turns a short feature request into an aligned plan folder, confirms decisions through questionnaires, splits approved work into executable phases, and gives smoke-test steps for user verification.

The default documentation, skills, agents, and workflow rules are written in English so they can be versioned as the canonical source. GitHub-visible Traditional Chinese documentation lives under `docs/i18n/`. Full local translation work can live under `translations/zh-TW/`, which is intentionally ignored by Git.

## Commands

Use these prompts after installing or enabling the plugin skill:

```text
/qdd {feature description}
/qdd-align
/qdd-plan
/qdd-phase {1~X}
/qdd-phase-all
/qdd-smoke {plan or phase}
```

Codex CLI has built-in slash commands, and custom reusable workflows are best packaged as skills/plugins. QDD therefore treats these command-shaped prompts as skill triggers. If a surface does not route custom slash text directly, invoke the skill explicitly with `/skills` or `$qdd-workflow`, then paste the same command text.

## Quick Install

For local development from this repository:

```powershell
.\scripts\install.ps1
```

From a fresh checkout:

```powershell
git clone https://github.com/starazzip/QDD-codex.git
cd QDD-codex
.\scripts\install.ps1
```

Or run the commands manually:

```powershell
codex plugin marketplace add .
codex plugin add qdd-codex@qdd-codex-local
```

If your Codex version reports a different local marketplace name, run:

```powershell
codex plugin marketplace list
codex plugin add qdd-codex@<marketplace-name>
```

Restart Codex or start a new thread after installing so the skill list refreshes.

## Workflow Summary

1. `/qdd {description}` creates `plans/<slug>/` with only alignment materials: `README.md`, `AGENTS.md`, and `questionnaire.md`.
2. `/qdd-align` reads the answered questionnaire, writes confirmed decisions to `decisions.md`, and appends follow-up questions when needed.
3. `/qdd-plan` creates phase files under `plans/<slug>/phases/` after the user confirms `decisions.md`.
4. `/qdd-phase {1~X}` executes selected phases.
5. `/qdd-phase-all` uses a tracked goal to complete every approved phase, then moves the plan to `plans/done/<slug>/`.
6. `/qdd-smoke {target}` writes detailed smoke-test steps for the requested plan or phase.

Plan folders under `plans/` are local workflow state and are ignored by Git.

## Design Rules

- This project targets the Codex ecosystem only.
- Keep canonical workflow content in English.
- Keep GitHub-visible Traditional Chinese docs under `docs/i18n/`.
- Keep full local Traditional Chinese translation work under `translations/zh-TW/` and out of version control.
- Prefer `AGENTS.md` for durable repository guidance, skills for reusable workflows, and plugins for installation.
- Keep the main Codex agent as implementer by default; repo-local `.codex/agents/*.toml` roles are read-oriented reviewers for planning, review, security, build failures, E2E verification, and cleanup.
- Do not create Claude-specific files, hooks, commands, or runtime configuration.
