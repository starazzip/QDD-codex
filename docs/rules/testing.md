# Testing Rules

- Every code-writing phase must include verification.
- Unit tests are required when logic can be isolated cheaply.
- BDD scenarios are required when behavior or acceptance criteria are ambiguous.
- E2E tests are required for critical user-facing flows when a runnable UI or integration path exists.
- If a test type is intentionally skipped, the phase must state why.
- Smoke-test instructions must be written for the user, not only for Codex.
